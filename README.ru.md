# AI Data Table Consultant

Веб-приложение для анализа табличных данных с помощью локальных LLM-моделей через Ollama.
Пользователь загружает CSV, XLS или XLSX, выбирает модель, после чего может задавать вопросы о данных на естественном языке.
AI анализирует данные через SQL-инструменты, а использованные колонки таблицы выделяются визуально.

## Идея проекта

AI Data Table Consultant превращает анализ табличных данных в обычный диалог с AI.
Вместо ручного написания формул и сложных фильтров пользователь задаёт вопрос естественным языком.
LangGraph управляет AI агентом, который может самостоятельно:

- получить схему таблицы;
- получить примеры данных;
- сформировать SQL;
- выполнить SQL через tool;
- обработать результат или ошибку;
- повторить выполнение при необходимости;
- сформировать итоговый ответ.

Пользователь получает не только ответ AI, но и визуальное понимание того, какие данные были использованы для формирования ответа.
Архитектура разделяет ответственность между компонентами:

- **Frontend** отвечает за интерфейс и отображение данных.
- **Backend** отвечает за API, хранение данных и интеграцию с AI.
- **LangGraph** отвечает за состояние и логику AI агента.
- **Ollama** отвечает за локальный запуск LLM.

## Возможности

- Просмотр данных в виде таблицы.
- Загрузка CSV, XLS и XLSX.
- Работа с локальными LLM через Ollama.
- Синхронизация моделей Ollama.
- Чат с AI по выбранной таблице.
- Потоковые ответы через Server-Sent Events (SSE).
- AI агент на основе LangGraph.
- Tool calling для работы с данными.
- Получение схемы и примеров данных.
- Генерация и выполнение SQL-запросов к данным.
- Подсветка колонок, использованных AI для расчетов.
- Отображение количества используемых токены.
- Отображение стоимости запроса (пока 0$, если не указать тариф).
- Пагинация таблиц.
- Поддержка Markdown в ответах AI.

## Архитектура

```
User
 │
 ▼
Next.js / React
 │
 │ POST /api/chat/stream
 ▼
FastAPI Backend
 │
 ▼
LangGraph
 │
 ├── assistant
 │     │
 │     └── LLM (ChatOllama)
 │
 ├── tools
 │     ├── get_dataset_schema
 │     ├── get_dataset_sample
 │     └── execute_sql
 │
 └──────────────┐
                │
                ▼
             Ollama
                │
                ▼
             Local LLM
```

LangGraph управляет состоянием и логикой AI агента:

```
START
  ↓
assistant
  ↓
tool_calls?
 ├── Да → tools
 │         ↓
 │      assistant
 │
 └── Нет → END
```

Это позволяет модели последовательно получать информацию о таблице с данными, выполнять SQL, обрабатывать результаты или ошибки и формировать итоговый ответ.

## LangGraph

LangGraph используется для создания AI агента и управления его состоянием и циклом выполнения.

Основные узлы:

- **assistant** — LLM на основе ChatOllama.
- **tools** — выполнение доступных инструментов.

Доступные инструменты позволяют:

- получать схему таблицы;
- получать срез данных;
- выполнять SQL-запросы, SQL-запроса

Общий цикл:

```
assistant
   ↓
tool call
   ↓
tools
   ↓
результат инструмента
   ↓
assistant
   ↓
итоговый ответ
```

LangGraph отделяет логику AI агента от API и frontend.

## Ollama

Ollama используется как локальный inference-сервис для запуска LLM.

Основное преимущество такого подхода — возможность использовать локальные модели без необходимости отправлять данные внешним AI-провайдерам.

Пример установки модели:

```bash
ollama pull llama3.1
```

Проверить установленные модели:

```bash
ollama list
```

### Синхронизация моделей Ollama

Приложение поддерживает синхронизацию моделей, установленных в Ollama, с моделями, доступными в приложении.

Например, если в Ollama была установлена новая модель:

```bash
ollama pull llama3.1
```

пользователь может нажать кнопку **Sync** в интерфейсе приложения.

После успешной синхронизации модель появится в выпадающем списке.


## Frontend

Frontend использует:

- Next.js
- React
- TypeScript
- Tailwind CSS
- react-markdown
- remark-gfm

Frontend отвечает за:

- отображение списка таблиц;
- отображение выбранной таблицы;
- пагинацию;
- загрузку CSV/XLS/XLSX файлов;
- выбор AI-модели;
- отправку вопросов AI;
- обработку потоковых SSE-ответов;

- отображение стоимости запросов;
- подсветку колонок, использованных AI;
- отображение ошибок.

## Backend

Backend является промежуточным API-слоем между frontend, базой данных и Ollama.

Backend отвечает за:

- загрузку и обработку файлов;
- хранение таблиц в виде файлов;
- предоставление строк таблиц;
- хранение информации о моделях;
- синхронизацию моделей с Ollama;
- обработку AI-запросов;
- управление AI агентом через LangGraph;
- выполнение tools;
- формирование потоковых ответов;
- передачу метаданных об использованных колонках;
- передачу token usage;
- расчёт стоимости запросов.


## Установка

### Переменные окружения

Frontend использует:

```
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Если переменная не задана, используется:

```
http://localhost:8000
```

Для development создайте файл:

```
.env.local
```

**Важно:** переменные с префиксом `NEXT_PUBLIC_` доступны клиентскому коду.

Не следует хранить секретные ключи, пароли и другие sensitive values в `NEXT_PUBLIC_*`.

## Docker

Frontend может запускаться через Docker.

Пример:

```bash
docker compose up --build
```

Текущий Dockerfile запускает Next.js в development-режиме.

## Подсветка AI-колонок

После выполнения AI-запроса backend передаёт metadata об использованных колонках.

Frontend использует эту информацию для визуальной подсветки соответствующих колонок таблицы.

Таким образом пользователь может видеть не только ответ AI, но и какие данные были использованы для его формирования.

## Примеры вопросов

После загрузки таблицы с данными пользователь может задавать вопросы естественным языком.

**Простые вопросы:**

- Какова общая сумма продаж?
- Сколько всего строк в таблице?
- Какой средний чек?
- Какая максимальная цена?
- Какая минимальная цена?

**Вопросы по группировке:**

- Какой товар продаётся лучше всего?
- Сравни продажи по категориям.
- Какая категория приносит больше всего выручки?
- Покажи топ-10 товаров по продажам.

**Фильтрация:**

- Покажи товары с продажами выше среднего.
- Какие товары стоят дороже 100?
- Найди записи за последний месяц.

**Сложный анализ:**

- Какие факторы сильнее всего влияют на продажи?
- Найди аномальные значения.
- Сравни продажи по месяцам.
- Какие категории имеют наибольший рост?
